TASK 2.1 — Authentication, bcrypt, JWT, and migration

Implement secure authentication for this Go/Gin/GORM LibraTrack API. Preserve the existing public API contract where possible. Add golang-migrate files `000003_add_auth_fields.up.sql` and `.down.sql` to add/remove `password_hash` and to change the user role default to `reader`; permit only `reader`, `librarian`, and `admin` in the final schema. Existing databases may already have migration version 3 applied, so preserve migration ordering and provide an idempotent compatibility migration if the existing seed migration must be renumbered. Add a `PasswordHash string` field to the User model with `json:"-"`. Never bind request JSON directly into a database model. Define explicit RegisterRequest and UpdateProfileRequest DTOs containing only fields users may edit. Registration must validate email/password, hash with `bcrypt.GenerateFromPassword([]byte(password), bcrypt.DefaultCost)`, assign role `reader` server-side, and return 422 for duplicate email. Login must use `bcrypt.CompareHashAndPassword`; unknown email and wrong password must return exactly the same HTTP 401 response with message `invalid credentials`. Issue a JWT signed only with `jwt.SigningMethodHS256`; load the signing key strictly from `os.Getenv("JWT_SECRET")`; include `user_id`, `role`, `iat`, and `exp`, with expiration exactly 24 hours after issue time. Do not log request bodies, passwords, tokens, or password hashes. Add tests for duplicate registration, valid login/token claims, generic login failures, and password-hash redaction.

TASK 2.2 — JWT middleware, RBAC, and route groups

Implement `internal/middleware/auth.go` and `internal/middleware/rbac.go` for the existing Gin application. AuthMiddleware must parse only `Authorization: Bearer <token>`, validate HS256 signature and expiration, and set typed `user_id` and `role` values in Gin context. Every authentication failure must call `c.AbortWithStatusJSON(401, ...)`; missing JWT_SECRET must fail closed with a generic 500. Implement variadic `RequireRole(allowed ...string)`: if no authenticated role is present, abort with 401; if the role is not allowed, abort with 403; never call the next handler after an abort. Register nested Gin groups in this order: public routes for register/login and GET books; protected routes using AuthMiddleware for GET/PUT `/me` and GET `/me/loans`; staff routes using AuthMiddleware first and RequireRole("librarian", "admin") second for book writes and loan checkout/return; admin routes using AuthMiddleware first and RequireRole("admin") second for GET `/users` and PUT `/users/:id/role`. Keep profile, registration, loan, and role update bodies as explicit DTOs. Add httptest integration coverage for missing/expired tokens, reader 403, staff/admin 201, and admin-only endpoints.
